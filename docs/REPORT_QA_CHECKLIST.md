## A. 사실 정확성 (25점)

### A1. 출처 없는 수치 검사 (10점)

보고서 내 모든 수치를 추출하여 아래 기준으로 검사한다.

```
검사 방법:
1. 보고서에서 숫자가 포함된 모든 문장 추출
2. 각 수치에 출처(URL) 존재 여부 확인
3. 출처가 Tier1·2인지 확인

감점 기준:
- 수치 1개당 출처 없음: -2점
- 출처가 Tier3 이하: -0.5점
- 블로그·광고성 출처: -3점 (즉시 삭제 필요)
```

### A2. 근거 없는 주장 검사 (10점)

```
검사 방법:
1. "~할 것이다", "~로 예상된다", "~가 필요하다" 패턴 문장 추출
2. 각 문장에 데이터 근거 존재 여부 확인
3. 근거 없이 의견만 서술된 문장 식별

감점 기준:
- 근거 없는 주장 1건당: -2점
- CEO Decision Point에 근거 없는 주장: -5점 (치명적 결함)
```

### A3. 최신성 검사 (5점)

```
검사 기준:
- 시장 데이터: 3년 이내 (2023년 이후)
- 경쟁사 정보: 12개월 이내
- 정책·규제: 현행 기준

감점 기준:
- 3년 이상 된 시장 수치 사용: -2점
- 1년 이상 된 경쟁사 정보 (최신 업데이트 없음): -2점
- 폐지된 정책 인용: -3점
```

## B. 출처 품질 (20점)

### B1. 출처 Tier 분포 (10점)

```
이상적 분포:
  Tier 1: 50% 이상
  Tier 2: 30% 이하
  Tier 3: 20% 이하
  사용 불가 출처: 0%

채점:
  Tier1 50% 이상: 10점
  Tier1 40~49%: 7점
  Tier1 30~39%: 4점
  Tier1 30% 미만: 0점 (재작성 필수)
```

### B2. URL 유효성 (5점)

```
검사 방법:
1. 보고서 내 모든 URL 목록 추출
2. 각 URL 접근 가능 여부 확인
3. 접근 불가 URL에 대체 출처 존재 여부 확인

감점 기준:
- URL 접근 불가 (대체 출처 없음) 1건당: -1점
```

### B3. 출처 다양성 (5점)

```
동일 기관 출처 집중 여부 검사.
단일 기관 출처가 50% 초과 시 편향 위험.

감점 기준:
- 단일 기관 출처 50~70%: -2점
- 단일 기관 출처 70% 초과: -5점
```

## C. Fact / Insight 분리 (15점)

### C1. 혼재 패턴 검사 (10점)

```
금지 패턴 (예시):
❌ "2023년 수검자는 1,746만명으로 다나아데이터에 유리한 상황이다."
   (수치[Fact]와 해석[Insight]이 한 문장에 혼재)

올바른 패턴:
✅ [Fact] 2023년 일반건강검진 수검자는 1,746만2,244명이다. (국민건강보험공단, 2024)
✅ [Insight] 이 중 59.8%가 질환의심·유질환자로, 검진 후 관리 서비스의 잠재 수요는 약 1,043만명이다.

검사 방법:
1. 수치 문장 추출
2. 동일 문장 내 해석·의견 혼재 여부 확인
3. 혼재 발견 시 분리 재작성

감점 기준:
- 혼재 문장 1건당: -1점
- CEO Report에 혼재: -2점 (고위험)
```

### C2. 섹션별 구분 검사 (5점)

```
보고서 구조에서 Fact Base 섹션과 Strategic Insight 섹션이
명확히 분리되어 있는지 확인.

감점 기준:
- Fact Base 섹션에 해석 혼입: -2점
- Insight 섹션에 출처 없는 새 수치 등장: -3점
```

## D. 전략 실행 가능성 (15점)

### D1. KPI 명시 여부 (8점)

```
모든 전략 제언에 KPI가 있는지 확인.

필수 KPI 형식:
[측정 지표] [목표 수치] [기한] [측정 방법]

예시:
✅ "비즈36.5 기업 고객사 수: 2026년 Q3까지 10개 → 20개 (전담 영업 인력 2명 투입)"
❌ "B2B 고객사를 확대한다"

감점 기준:
- KPI 없는 전략 제언 1건당: -2점
- 기한 없는 KPI: -1점
- 측정 불가능한 KPI ("만족도 향상"): -1점
```

### D2. 자원 명시 여부 (4점)

```
전략 실행에 필요한 자원이 명시되어 있는지 확인.

필수 자원 항목:
- 인력 (몇 명, 어떤 역할)
- 예산 (범위 또는 비율)
- 기간 (시작~종료)
- 파트너십 (필요 시)

감점 기준:
- 자원 명시 없는 전략 제언: -2점
```

### D3. 우선순위 명시 여부 (3점)

```
복수의 전략 제언이 있을 때 우선순위(1, 2, 3위)가
명확히 표시되어 있는지 확인.

감점 기준:
- 우선순위 없는 복수 전략 제언: -3점
```

## E. CEO 의사결정 가능성 (15점)

### E1. CEO Decision Point 존재 여부 (5점)

```
보고서 내 CEO Decision Point 섹션이 존재하고,
2개 이상 5개 이하의 Decision Point가 포함되어 있는지 확인.

감점 기준:
- Decision Point 섹션 없음: -5점 (즉시 재작성)
- Decision Point 1개 이하: -3점
- Decision Point 6개 이상 (과도): -1점
```

### E2. Decision Point 품질 (7점)

```
각 Decision Point를 아래 기준으로 검사:

필수 요소 (각 1점):
□ 명확한 질문 형태 (1문장 의문문)
□ 2~3개 선택지 제시
□ 각 선택지 기대 효과 명시
□ 각 선택지 리스크 명시
□ 권고안 1개 + 근거 명시
□ 결정 기한 명시
□ 추상적 표현 없음 ("혁신이 필요하다" 금지)

감점 기준:
- 필수 요소 누락 1건당: -1점
```

### E3. 30초 테스트 (3점)

```
CEO가 Executive Summary만 읽고 30초 내에 아래 3가지를 파악할 수 있는지 확인:

1. 지금 가장 중요한 기회 또는 위협은 무엇인가?
2. 내가 결정해야 할 가장 중요한 사안은 무엇인가?
3. 언제까지 결정해야 하는가?

3가지 모두 파악 가능: 3점
2가지: 2점
1가지: 1점
0가지: 0점 (Executive Summary 재작성 필수)
```


## QA 실행 절차

### Step 1. 자동 검사 (Claude Code 실행)

```
1. 보고서 텍스트에서 수치 포함 문장 추출
2. 각 수치의 출처 태그 존재 여부 확인
3. 출처 URL 유효성 검사
4. Fact/Insight 혼재 패턴 탐지
5. KPI 형식 준수 여부 확인
6. CEO Decision Point 존재 및 형식 확인
```

### Step 2. 점수 산출

```
각 항목별 감점 합산
QA Score = 100 - 총 감점

출력 형식:
---
QA Report
보고서명: [제목]
검사일: [날짜]
---
A. 사실 정확성:    [점수]/25
B. 출처 품질:      [점수]/20
C. Fact/Insight:   [점수]/15
D. 실행 가능성:    [점수]/15
E. CEO 의사결정:   [점수]/15
F. 형식 준수:      [점수]/10
---
총점: [QA Score]/100
판정: [합격 / 재작성 필요]
---
주요 결함:
1. [결함 내용] → [수정 방향]
2. ...
---
```

### Step 3. 판정

```
95점 이상: 합격 → 발행 승인
90~94점: 조건부 합격 → 지적 사항 수정 후 발행
90점 미만: 재작성 → QA 재실행
```

### Step 4. 재작성 가이드

```
재작성 시 반드시 다음 순서로 진행:
1. QA Report의 주요 결함 목록 확인
2. 결함 항목을 우선순위 순으로 수정
3. 수정 완료 후 QA 재실행
4. 95점 미만이면 Step 2로 복귀

단, 동일 보고서에 대해 재작성은 최대 2회.
2회 재작성 후에도 95점 미만이면
→ 데이터 수집 단계부터 재시작
```
